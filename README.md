# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В приложении используются два интерфейса `IProduct` и `IBuyer`, ими описаны данные — товар и покупатель.

#### Тип `TPayment`
Данный тип описывает возможные способы оплаты товаров в корзине.

```ts
type TPayment = 'card' | 'cash';
```

Значения:
`card` — оплата картой онлайн.  
`cash` — оплата наличными.


#### Интерфейс `IProduct`
Интерфейс описывает товар, доступный для просмотра и заказа в каталоге веб-ларька.

```ts
interface IProduct {
    id: string;
    title: string;
    image: string;
    category: string;
    price: number | null;
    description: string;
}
```

Поля интерфейса:
`id: string` - уникальный идентификатор товара.
`title: string` - название товара.
`image: string` - путь к картинке товара. 
`category: string` - категория товара. 
`price: number | null` - цена товара. Если значение `null`, тогда товар недоступен для покупки.
`description: string` - подробное описание товара.


#### Интерфейс `IBuyer`
Интерфейс описывает данные покупателя и выбранный способ оплаты, который указывается пользователем при заполнении формы при заказе.

```ts
interface IBuyer {
    payment: TPayment | null;
    address: string;
    email: string;
    phone: string;
}
```

Поля интерфейса:
`payment: TPayment | null` - выбранный способ оплаты.
`address: string` - адрес покупателя.
`email: string` - E-mail адрес покупателя.
`phone: string` - номер телефона покупателя.


#### Интерфейс `IValidateData`
Интерфейс описывает объект, который может содержать ошибки, если пользователь не указал какие-то данные при оформлении заказа.

```ts
interface IValidateData {
    payment?: string;
    address?: string;
    email?: string;
    phone?: string;
}
```

Поля интерфейса:
`payment?: string` - ошибка если не указан способ оплаты.
`address?: string` - ошибка если не указан адрес.
`email?: string` - ошибка если не указан E-mail.
`phone?: string` - ошибка если не указан номер телефона.


#### Интерфейс `IProductsResponse`
Данный интерфейс описывает объект, который приложение получает при запросе списка товаров с сервера.

```ts
export interface IProductsResponse {
    total: number;
    items: IProduct[];
}
```

Поля интерфейса:
`total: number` - количество карточек товаров в списке.
`items: IProduct[]` - список товаров.


#### Интерфейс `IOrder`
Данный интерфейс наследует свойства интерфейса IBuyer и описывает объект, который приложение передаёт на сервер при оформлении заказа.

```ts
interface IOrder extends IBuyer {
    total: number;
    items: string[];
}
```

Поля интерфейса:
`total: number` - итоговая стоимость всех товаров в заказе.
`items: string[]` - массив уникальных идентификационных номеров товаров в заказе.


#### Интерфейс `IOrderResponse`
Данный интерфейс описывает объект, который приложение получает с сервера при успешном оформлении заказа.

```ts
interface IOrderResponse {
    id: string;
    total: number;
}
```

Поля интерфейса:
`id: string` - уникальный идетификационный номер заказа.
`total: number` - итоговая стоимость всех товаров в заказе.


### Модели данных

#### Класс `ProductsCatalog`
Класс отвечает за хранение карточек товаров, полученных с сервера и за хранение выбранной карточки товара для подробного просмотра в модальном окне.

Конструктор:
`constructor(protected events: IEvents)` -  инициализирует пустой массив товаров для выбранного товара. Сохраняет ссылку на систему событий.

Поля класса:
`productsList: IProduct[]` - массив всех товаров.
`selectedProduct: IProduct` - карточка товара, выбранная для подробного просмотра в модальном окне.

Методы:  
`setProductsList(products: IProduct[]): void` - сохраняет массив товаров.
`getProductsList(): IProduct[]` - возвращает массив товаров.
`getProduct(id: string): IProduct | undefined` - возвращает карточку товара по его уникальному идентификатору.
`setSelectedProduct(id: string): void` - сохраняет выбранную карточку товара для подробного просмотра.
`getSelectedProduct(): IProduct | null` - возвращает выбранную карточку товара.

#### Класс `ShoppingCart`
Класс отвечает за хранение карточек товаров, которые пользователь добавил в корзину для покупки и позволяет управлять ими: добавлять, удалять и вести подсчет.

Конструктор:
`constructor(protected events: IEvents)` - инициализирует пустую коллекцию товаров. Сохраняет ссылку на систему событий.  

Поля класса:
`productsList: IProduct[]` - масссив товаров добавленных в корзину.

Методы:  
`addProduct(product: IProduct): void` - добавляет товар, который был получен в параметре, в массив корзины.
`getProductsList(): IProduct[]` - возвращает массив товаров, которые находятся в корзине.
`removeProduct(id: string): void` - удаляет товар, полученный в параметре из массива корзины.
`clearShoppingCart(): void` - очищает корзину.
`getNumberOfProducts(): number` - возвращает количество товаров в корзине.
`getTotalPrice(): number` - возвращает стоимость всех товаров в корзине.
`checkProduct(id: string): boolean` - проверяет наличие товара в корзине по его id, полученного в параметр метода.

#### Класс `Buyer`
Класс отвечает за хранение данных покупателя указанных при оформлении заказа, валидацию этих данных и позволяет очищать данные. 

Конструктор:
`constructor(protected events: IEvents)` -  инициализирует хранилище данных (обычно пустым объектом) и объект ошибок. Сохраняет ссылку на систему событий.   

Поля класса:
`payment: TPayment | null` - способ оплаты, если не выбран, тогда null.
`address: string` - адрес покупателя.
`email: string` - E-mail адрес покупателя.
`phone: string` - номер телефона покупателя.

Методы:  
`setData(data: Partial<IBuyer>): void` - сохраняет данные в модели, реализована возможность сохранить только одно значение, не удалив при этом значения других полей, которые уже могут храниться в классе.
`getData(): IBuyer` - возвращает все данные покупателя.
`clearData(): void` - очищает данные покупателя.
`validateData(): IValidateData` - проверяет данные на валидность. Поле является валидым, если оно не пустое. Предоставляет информацию об ошибке, связанной с проверкой конкретного значения.

### Слой коммуникации
#### Класс `Communication`
Класс реализует слой коммуникации приложения и отвечает за взаимодействие с API.

Конструктор:
`constructor(private api: IApi)` -  принимает объект, соответствующий интерфейсу IApi.   

Поля класса:
`api: IApi` - поле private.

Методы:  
`getProducts(): Promise<IProductsResponse>` - направляет get запрос на эндпоинт /product/ и возвращает объект, полученный от сервера, в котором находится массив товаров.
`createOrder(orderData: IOrder): Promise<IOrderResponse>` - направляет post запрос на эндпоинт /order/ и передаёт в него данные, полученные в параметрах метода, а возвращает объект, подтверждающий покупку на определенную сумму.

### Слой представления (View)
#### Класс `Header`
Это компонент верхней панели интерфейса. Его главная задача — отображать текущее состояние корзины (количество товаров) и предоставлять пользователю быстрый доступ к просмотру содержимого корзины. Он не хранит данные о товарах, а лишь визуализирует переданную ему информацию и транслирует действия пользователя дальше по системе событий. Наследуется от базового класса `Component`. Это дает ему стандартную инфраструктуру для работы с DOM-контейнером и типизацией ожидаемых данных.

Используемые интерфейсы:
`IHeader`: описывает структуру данных, которые компонент ожидает получить для отрисовки (в данном случае — поле `counter: number`, содержащее количество товаров).
`IEvents`: интерфейс системы событий, передаваемый в конструктор для связи с остальной частью приложения.

Конструктор:
`constructor(container: HTMLElement, protected events: IEvents)` - инициализирует базовый класс Component. Через утилиту ensureElement находит элементы счетчика и кнопки внутри переданного контейнера. Вешает обработчик клика на кнопку корзины. При клике эмитится событие `cart:open`, которое перехватывает главный презентер и открывает модальное окно корзины.

Поля класса:
`counterElement: HTMLElement` - ссылка на DOM-элемент, отображающий цифру количества товаров (например, .header__basket-counter).
`cartButtonElement: HTMLButtonElement` - ссылка на кнопку открытия корзины (например, .header__basket).
`events: IEvents` - экземпляр эмиттера событий, необходимый для отправки сообщений о действиях пользователя.

Сеттеры:
`set counter(value: number)` - принимает числовое значение количества товаров. Преобразует число в строку и обновляет текстовое содержимое элемента `counterElement`. Это позволяет синхронизировать цифру в шапке с реальным состоянием модели `ShoppingCart` без прямой зависимости между ними.

#### Класс `Gallery`
Это контейнер-обёртка для отображения списка карточек товаров. Его главная задача — принимать массив готовых DOM-элементов (карточек) и корректно вставлять их в свой контейнер, заменяя предыдущее содержимое. Он не занимается логикой формирования списка (не решает, какие товары показывать или в каком порядке), а лишь отвечает за чистое и быстрое обновление визуальной части витрины. Наследуется от базового класса `Component`. Это обеспечивает ему стандартную структуру компонента, типизацию и доступ к базовым методам работы с DOM.

Используемые интерфейсы:
`IGallery` - описывает структуру данных, которые компонент ожидает получить для отрисовки. В данном случае содержит единственное поле `catalog: HTMLElement[]` — массив DOM-элементов, представляющих карточки товаров.

Конструктор:
`constructor(container: HTMLElement)` - инициализирует базовый класс `Component`. Присваивает переданный контейнер полю `catalogElement`. На данном этапе класс не выполняет поиск вложенных элементов, так как предполагается, что весь контейнер целиком служит областью для вывода списка.

Поля класса:
`catalogElement: HTMLElement` - ссылка на DOM-контейнер, внутрь которого будут вставляться карточки товаров. В текущей реализации он совпадает с корневым контейнером, переданным в конструктор.

Сеттеры:
`set catalog(items: HTMLElement[])` - принимает массив DOM-элементов (обычно это экземпляры `CardCatalog`, созданные заранее). Вызывает на целевом элементе метод `replaceChildren(...items)`, который удаляет все текущие дочерние элементы и вставляет новые. Гарантирует, что в контейнере всегда отображается актуальный список товаров, переданный извне.

#### Класс `Modal`
Это универсальный компонент для отображения всплывающих окон поверх основного контента. Его главная задача — управлять видимостью модального окна (открытие/закрытие), монтировать внутрь произвольный контент (карточки товаров, формы заказа, экраны успеха) и обеспечивать корректную передачу событий от вложенных элементов. Он абстрагирует работу с DOM-структурой модального окна, позволяя другим частям приложения просто говорить: «покажи это» или «закрой». Наследуется от базового класса `Component`. Это дает ему стандартный интерфейс для инициализации и работы с DOM-элементом.

Используемые интерфейсы:
`IEvents` - интерфейс системы событий, передаваемый в конструктор. Необходим для трансляции событий от вложенного контента (например, нажатия кнопки «Закрыть» внутри экрана успеха) наружу, в презентер.

Конструктор:
`constructor(container: HTMLElement, protected events: IEvents)` - инициализирует базовый класс `Component`. Сохраняет ссылку на переданный контейнер.

Поля класса:
`container: HTMLElement` - ссылка на корневой DOM-элемент модального окна (например, #modal-container). Отвечает за общую структуру окна.
`contentContainer: HTMLElement` - ссылка на внутреннюю область, куда монтируется пользовательский контент.
`events: IEvents` - экземпляр эмиттера событий для связи с презентером.

Методы:
`open()` - делает модальное окно видимым.
`close()` - скрывает модальное окно.

Сеттеры:
`set content(value: HTMLElement)` - при присваивании значения сеттер автоматически очищает текущий контент и вставляет новый. Это предотвращает накопление старых элементов в DOM.

#### Класс `Cart`
Это компонент, отвечающий за визуализацию содержимого корзины в модальном окне. Его главная задача — отображать список товаров (с возможностью удаления), показывать итоговую сумму заказа и управлять доступностью кнопки оформления. Он не хранит данные о товарах, а получает их извне (из модели `ShoppingCart`) и отображает актуальное состояние. Также он транслирует действия пользователя (например, нажатие кнопки «Оформить») через систему событий. Наследуется от базового класса `Component`. Это обеспечивает ему стандартную инфраструктуру для работы с DOM-контейнером, типизацией ожидаемых данных и базовыми методами инициализации.

Используемые интерфейсы:
`ICart` - описывает структуру данных, которые компонент ожидает получить для отрисовки. Содержит поля `cartList: HTMLElement[]` (список карточек товаров) и `totalPrice: number` (общая сумма).

Конструктор:
`constructor(container: HTMLElement, protected events: IEvents)` - инициализирует базовый класс Component. Через утилиту ensureElement находит внутри переданного контейнера элементы для списка, цены и кнопки. Это гарантирует, что компонент не упадет, если какой-то элемент отсутствует в разметке, а сразу сообщит об ошибке. Вешает обработчик клика на кнопку оформления заказа. При нажатии эмитится событие `cart:order`, которое перехватывает главный файл приложения и инициирует переход к форме выбора оплаты.

Поля класса:
`cartListElement: HTMLElement` - ссылка на контейнер списка товаров (например, .basket__list), куда будут вставляться карточки позиций.
`totalPriceElement: HTMLElement` - ссылка на элемент, отображающий итоговую сумму (например, .basket__price).
`cartButtonElement: HTMLButtonElement` - ссылка на кнопку оформления заказа (например, .basket__button).
`events: IEvents` - экземпляр эмиттера событий для связи с презентером.

Сеттеры:
`set cartList(items: HTMLElement[])` - принимает массив DOM-элементов. Использует метод replaceChildren(...items) для полной замены содержимого списка. Позволяет презентеру полностью пересобрать список товаров в корзине при любом изменении (добавление, удаление, изменение количества).
`set totalPrice(value: number)` - принимает числовое значение итоговой суммы. Форматирует его и записывает в текстовое содержимое элемента `totalPriceElement`, добавляя единицу измерения («синапсов»).
`set buttonDisabled(value: boolean)` - принимает булево значение. Устанавливает свойство disabled у кнопки оформления заказа. Реализует логику: если корзина пуста, кнопка оформления должна быть неактивна. Это предотвращает попытку оформить пустой заказ.

#### Класс `Card`
Это абстрактный базовый класс, который определяет единый интерфейс и общую логику для всех видов карточек товара в проекте. Он не предназначен для прямого создания экземпляров, а служит «чертежом» для конкретных реализаций: `CardCatalog`, `CardPreview` и `CardInCart`. Его главная задача — гарантировать, что любая карточка умеет находить свои внутренние элементы, отображать базовые данные (заголовок, цену, картинку) и реагировать на действия пользователя. Наследуется от базового класса `Component`. Это дает ему доступ к общей инфраструктуре работы с DOM-контейнером.

Используемые интерфейсы:
`ICardActions` - интерфейс, описывающий действия, которые можно привязать к карточке. Позволяет передавать логику реакции на событие из внешнего мира.

Конструктор:
`constructor(container: HTMLElement, actions?: ICardActions)` - инициализирует базовый класс Component. Сохраняет ссылку на контейнер и объект действий.

Поля класса:
`titleElement: HTMLElement` - ссылка на элемент заголовка товара.
`priceElement: HTMLElement` - ссылка на элемент цены.
`imageElement: HTMLImageElement` - ссылка на тег <img> для отображения картинки.
`container: HTMLElement` - корневой контейнер карточки (передается в конструктор).
`actions?: ICardActions` - опциональный объект с действиями (например, обработчик клика), переданный при создании карточки.

Сеттеры:
`set title(value: string)` - принимает строку и записывает её в `titleElement.textContent`. Дает простой способ обновить заголовок карточки из внешнего кода.
`set price(value: number | null)` - принимает число или null. Если цена null, может показывать заглушку «Бесценно».
`set image(value: string)` - принимает путь к изображению и вызывает внутренний метод `setImage`, подставляя базовый URL (CDN) и alt-текст.

#### Класс `CardCatalog`

Его главная задача — быть «строительным блоком» для `Gallery`: создаваться, отображать минимум необходимой информации (картинка, категория, заголовок, цена) и реагировать на клик пользователя, открывая детальный просмотр. Наследуется от `Card`. Это позволяет ему использовать всю общую инфраструктуру базового класса (setImage, сеттеры для цены/заголовка). =

Используемые интерфейсы:
`ICardActions` - интерфейс действий. В случае `CardCatalog` сюда обычно передают обработчик клика, который срабатывает, когда пользователь нажимает на карточку.
`TCardCatalog` - вспомогательный тип (Pick<IProduct, 'image' | 'category' | 'title' | 'price'>), который явно ограничивает набор данных, необходимых именно для этой карточки.

Конструктор:

Это делает всю карточку кликабельной зоной.

Поля класса:

`container: HTMLElement` - корневой контейнер карточки (создается из шаблона #card-catalog).
`actions?: ICardActions` - опциональный объект с действиями (в основном, обработчик клика).

Сеттеры:
`set category(value: TCategory)` - принимает значение категории. Записывает название категории в текстовый элемент.
`set image(value: string)` - принимает относительный путь к изображению (например, /images/phone.svg). Вызывает защищенный метод родителя this.setImage, автоматически подставляя базовый URL (CDN_URL + value) и используя заголовок товара (this.title) как альтернативный текст (alt).

#### Класс `CardPreview`
Это карточка товара, предназначенная для отображения в модальном окне. Здесь пользователь должен видеть максимум полезной информации: крупное изображение, полное название, категорию, цену, подробное описание и главное — иметь возможность совершить действие (купить или удалить, если товар уже в корзине). Его главная задача — служить интерфейсом для принятия решения о покупке внутри всплывающего окна. Наследуется от `Card`. Позволяет использовать общую логику работы с изображением, заголовком и ценой из базового класса.

Используемые интерфейсы:

`ICardActions` - интерфейс действий. В случае превью сюда передают обработчик клика по кнопке действия («Купить» или «Удалить»).

`imageElement: HTMLImageElement` - ссылка на крупное изображение товара.

#### Класс `Form`
Это абстрактный базовый класс, который задает единый стандарт поведения для всех форм в приложении. Он не предназначен для прямого создания экземпляров, а служит фундаментом для конкретных форм (например, `FormContacts`, `FormOrder`). Его главная задача — централизовать общую логику работы с формами: обработку отправки, отслеживание изменений в полях ввода, управление состоянием кнопки отправки и отображение ошибок. Это избавляет дочерние классы от дублирования кода и гарантирует, что все формы в проекте ведут себя предсказуемо. Наследуется от `Component`. Получает базовую инфраструктуру для работы с DOM-контейнером.

Используемые интерфейсы:
`IEvents` - интерфейс системы событий. Критически важен для Form, так как форма не должна сама отправлять данные на сервер или валидировать их. Она лишь сообщает: «Пользователь ввел данные» или «Пользователь нажал отправить».
`IForm` - описывает структуру данных, которые форма ожидает получить или вернуть.

Конструктор:
`constructor(container: HTMLFormElement, protected events: IEvents)` - инициализирует базовый класс Component. Через ensureElement находит кнопку отправки и блок ошибок. Вешает глобальные слушатели событий на всю форму: 1. submit: Перехватывает стандартную отправку формы браузером `event.preventDefault()`, чтобы страница не перезагружалась, и эмитит событие `${container.name}:submit`. Имя формы берется из атрибута name тега <form>, что позволяет разным формам генерировать уникальные события. 2. input: Слушает изменения во всех полях ввода внутри формы. При каждом вводе определяет, какое именно поле изменилось `target.name`, берет его значение и эмитит событие `form:change` с объектом `{ fieldName, fieldValue }`. Это позволяет презентеру реагировать на ввод в реальном времени (например, запускать валидацию).

Поля класса:
`buttonSubmit: HTMLButtonElement` - ссылка на кнопку отправки формы (обычно type="submit"). Используется для управления её состоянием (активна/неактивна).
`errorElement: HTMLElement` - ссылка на контейнер для отображения сообщений об ошибках валидации.
`container: HTMLFormElement` - корневой элемент формы, переданный в конструктор.
`events: IEvents` - экземпляр эмиттера событий для связи с внешним миром.

Сеттеры:
`set valid(value: boolean)` - принимает булево значение. Устанавливает свойство `disabled` у кнопки отправки `this.buttonSubmit.disabled = !value`.
`set error(value: string)` - принимает строку с сообщением об ошибке. Записывает её в `this.errorElement.textContent`. 

#### Класс `FormOrder`
Это конкретная реализация формы, предназначенная для первого этапа оформления заказа. Она позволяет пользователю выбрать способ оплаты (картой или наличными) и указать адрес доставки. В отличие от базового класса Form, этот компонент добавляет специфичную интерактивность: визуальное переключение кнопок оплаты и динамическое управление состоянием кнопки отправки на основе валидности данных. Его задача — собрать критически важные параметры заказа и передать их дальше по цепочке событий, гарантируя, что пользователь не сможет отправить форму с пустыми или некорректными данными. Наследуется от `Form`. Получает всю общую инфраструктуру: перехват событий submit и input, управление кнопкой отправки через сеттер valid, отображение ошибок через сеттер error.

Используемые интерфейсы:

`IFormOrder` - интерфейс, определяющий ожидаемые данные формы (способ оплаты и адрес).

Конструктор:
`constructor(container: HTMLFormElement, protected events: IEvents)` - вызывает конструктор родителя super(container, events), инициализируя общую логику форм (перехват submit/input, поиск кнопки отправки и блока ошибок). Через ensureElement находит специфические элементы этой формы: две кнопки оплаты и поле адреса. 
Вешает обработчики клика на кнопки оплаты: При нажатии на кнопку «Картой» или «Наличными» форма не меняет данные сама, а эмитит событие `payment:change` с выбранным типом оплаты. Это позволяет контроллеру обновить модель данных `Buyer` и синхронизировать состояние других частей интерфейса.

Поля класса:
`cardPaymentElement: HTMLButtonElement` - ссылка на кнопку выбора оплаты картой.
`cashPaymentElement: HTMLButtonElement` - ссылка на кнопку выбора оплаты наличными.
`addressElement: HTMLInputElement` - ссылка на текстовое поле для ввода адреса доставки.
`container: HTMLFormElement` - корневой контейнер формы.
`events: IEvents` - экземпляр эмиттера событий для связи с контроллером.

Сеттеры:
`set payment(value: TPayment)` - принимает выбранный способ оплаты ("card" или "cash"). Использует classList.toggle для добавления класса .button_alt-active соответствующей кнопке. Это делает выбор пользователя очевидным без необходимости смотреть на состояние модели.
`set address(value: string)` - принимает строку с адресом. Напрямую присваивает значение в поле ввода: `this.addressElement.value = value`.

#### Класс `FormContacts`
Это конкретная реализация формы, предназначенная для второго этапа оформления заказа. Она собирает контактные данные покупателя: email и номер телефона. В отличие от формы выбора оплаты, здесь акцент сделан на валидации текстовых полей и мгновенной обратной связи с пользователем. Её главная задача — гарантировать, что у переданы будут корректные контакты для связи, и предотвратить отправку формы, если обязательные поля пусты или заполнены неверно. Наследуется от `Form`. Используемые интерфейсы:
`IFormContacts` - интерфейс, определяющий ожидаемые данные формы (email и телефон).

`events: IEvents` - экземпляр эмиттера событий.

Сеттеры:
`set eMail(value: string)` - принимает строку с email-адресом. Записывает значение напрямую в свойство value поля ввода: `this.emailElement.value = value`.
`set phone(value: string)` - принимает строку с номером телефона. Записывает значение в `this.phoneElement.value`.

#### Класс `Success`
Это компонент, который отображает финальное сообщение пользователю после успешной отправки заказа на сервер. Его главная задача — дать пользователю понятную обратную связь: «Ваш заказ принят!», показать итоговую сумму и предоставить возможность закрыть окно. Компонент отображения, который лишь визуализирует переданные ему данные и реализует одно действие: закрыть экран. Наследуется от `Component`. Получает стандартную инфраструктуру для работы с DOM-контейнером.

Используемые интерфейсы:
`ISuccess` - интерфейс, описывающий данные, необходимые для отрисовки экрана успеха.

Конструктор:
`constructor(container: HTMLElement, protected events: IEvents)` - инициализирует базовый класс Component. Через ensureElement находит внутри шаблона элементы для отображения цены и кнопки закрытия. Вешает обработчик клика на кнопку закрытия: При нажатии эмитится событие `success:close`.

Поля класса:
`priceElement: HTMLElement` - ссылка на элемент, куда будет выведена итоговая сумма заказа (блок с текстом «Итого: X синапсов»).
`closeButtonElement: HTMLButtonElement` - ссылка на кнопку «Закрыть», которая позволяет пользователю убрать модальное окно.
`container: HTMLElement` - корневой контейнер компонента, созданный из шаблона #success.

Сеттеры:
`set price(value: number)` - принимает числовое значение итоговой суммы заказа. Форматирует и записывает его в `priceElement.textContent`.


### Презентер
Презентер реализован в основном скрипте в файле `main.ts`.
Что делает презентер в контексте этого приложения:
1. Синхронизация состояния - собирает данные и раздает их компонентам.
2. Обработка действий - слушает события от компонентов и реагирует на них.
3. Бизнес-логика - валидирует данные и управляет логикой.
4. Маппинг - связывает UI с данными.

### События приложения
`products:changed` - синхронизация каталога товаров (смысл: «Товары обновились → перерисуй витрину»).
Что происходит внутри: загрузка товаров с сервера или их изменение => берется список товаров из модели => для каждого товара создатся карточка `CardCatalog` => подставляются данные продукта, путь к изображению заменяется с svg на png => отдается готовый массив карточек в `Gallery`.

`catalog:click-card` - выбор товара в каталоге (смысл: «Пользователь кликнул на товар → запомни, какой именно, чтобы потом показать подробности»).
Что происходит внутри: сохраняет ID выбранного товара в модели ProductsCatalog.

`preview:changed` - модальное окно, открытие превью (смысл: «Пора показать детальную карточку → найди товар, подготовь кнопку и открой окно»).
Что происходит внутри: берем выбранный товар из модели => заполняем данными карточку-превью `CardPreview` => меняем текст кнопки: «Купить» или «Удалить из корзины» (зависит от того, есть ли товар уже в корзине) => показываем модальное окно `Modal` с этим превью.

`preview:click-button` - (Купить / Удалить) действие в превью (смысл: «Нажали кнопку в окне → добавь или удали товар, обнови цифры, закрой окно»).
Что происходит внутри: проверяем: есть ли товар в корзине => если есть: удаляем из корзины => если нет: добавляем в корзину => обновляем счетчик в шапке `Header` => закрываем окно.

`cart:open` - открытие корзины (смысл: «Пользователь хочет видеть корзину → проверь, можно ли что-то заказать, и покажи список товаров»).
Что происходит внутри: проверяем, пуста ли корзина. Если да — блокируем кнопку оформления заказа => показываем модальное окно с содержимым корзины `Cart`.

`cart:order` - переход к форме, оформление заказа (смысл: «Нажали "Оформить" → покажи форму выбора оплаты и указания адреса»).
Что происходит внутри: показываем модальное окно с формой выбора способа оплаты и адреса `FormOrder`.

`cart:changed` - обновление корзины (смысл: «Состав корзины изменился → пересчитай сумму, обнови список и цифры везде»).
Что происходит внутри: обновляем счетчик в шапке => генерируем новые карточки товаров для корзины `CardInCart` и отдаем их в компонент `Cart` => считаем и показываем итоговую сумму => если корзина пуста — блокируем кнопку заказа.

`cart:remove` - удаление товара из корзины (смысл: «Пользователь хочет удалить товар → скажи модели: "удали этот товар"»).
Что происходит внутри: вызываем метод модели `ShoppingCart`, чтобы удалить товар по его ID.

`payment:change` - выбор способа оплаты (смысл: «Выбрали оплату → запомни выбор в данных, чтобы потом отправить его на сервер»).
Что происходит внутри: сохраняем выбранный способ оплаты в модель `Buyer`.

`form:change` - ввод данных в формы (Адрес, Email, Телефон) (смысл: «Пользователь что-то напечатал → сразу сохрани это в общую модель данных». Это позволяет валидировать данные в реальном времени).
Что происходит внутри: смотрим, какое именно поле изменилось `fieldName`, и обновляем соответствующее поле в модели `Buyer`. Если ввели адрес → `buyerModel.setData({address: ...})` * Если ввели email → `buyerModel.setData({email: ...})`.

`order:submit` - переход к контактам (после выбора оплаты) (смысл: «Готово с оплатой → открой форму для ввода телефона и почты»).
Что происходит внутри: показываем модальное окно со второй формой — для ввода контактов `FormContacts`.

`buyer:changed` - валидация и подготовка форм к отображению (смысл: «Данные изменились → проверь, всё ли правильно, покажи ошибки, если есть, и обнови состояние кнопок». Обрати внимание, что этот обработчик срабатывает каждый раз, когда меняется хоть одно поле. Это гарантирует, что кнопка «Заказать» будет неактивна, пока пользователь не заполнит все обязательные поля).
Что происходит внутри: обработчик забирает все данные из модели => запускает валидацию `buyerModel.validateData()` => собирает список ошибок для формы оплаты и формы контактов => включает/выключает кнопку отправки в обеих формах (если есть ошибки — кнопка неактивна) => выводит текст ошибок => заполняет поля форм текущими данными из модели (чтобы при ошибке данные не пропали).

`contacts:submit` - финальная отправка заказа (смысл: «Пользователь подтвердил заказ → собери всё вместе, отправь на сервер, покажи результат и очисти корзину).
Что происходит внутри: собираем итоговый объект заказа (оплата, адрес, контакты, общая сумма, список ID товаров) => отправляем запрос на сервер через `communication.createOrder(order)` => если успех: показываем окно «Успех» `Success`, очищаем корзину и данные покупателя => если ошибка: ловим её и пишем в консоль. 

`success:close` - закрытие финального экрана `Success` (смысл: «Убери это окно с экрана»).
Что происходит внутри: вызываем `modal.close()`, чтобы убрать модальное окно с экрана.
